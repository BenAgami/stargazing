<objective>
Fix the picker round-trip in the workout builder so the builder screen is no longer remounted when the user adds an exercise — exercises append correctly, and edit-mode workout id survives the round-trip.

Purpose: Tests 7 and 8 from 03-UAT.md both fail because `router.replace` in `exercise-detail.tsx` creates a new `/workout-builder` screen instance on the stack. The new instance remounts with `useState([])`, dropping all draft state (name, exercises) and losing the `id` param in edit mode. Symptom: only one exercise can ever be added; edit mode silently drops the workout id and saves a new workout.

Output: A module-level `pickedExerciseStore` that hands off the selected exercise without URL params, plus updates to `exercise-detail.tsx` (uses `router.dismiss(2)` to pop catalog + detail back to the existing builder) and `workout-builder.tsx` (consumes the store on focus instead of reading `pickedExercise*` from `useLocalSearchParams`).
</objective>

  <name>Task 1: Create pickedExerciseStore (module-level singleton)</name>
  <files>apps/native/src/state/pickedExerciseStore.ts</files>
  <behavior>
    - `setPickedExercise(picked)` stores a `PickedExercise` value in module-level state.
    - `consumePickedExercise()` returns the current value AND clears it atomically — calling consume twice in a row returns `undefined` the second time.
    - The type `PickedExercise` matches the input shape of `useWorkoutBuilder.addExercise`.
    - Module state is intentionally NOT persisted — it is a transient hand-off slot.
  </behavior>
  <action>
    Create new directory `apps/native/src/state/` and add `pickedExerciseStore.ts`. This is a deliberately minimal module-level singleton — no Zustand, no Context (Zustand is not installed; package.json was checked). React 19's `useSyncExternalStore` is not needed because the builder screen reads the value imperatively inside `useFocusEffect`, not as reactive state.

    Implementation:

    ```typescript
    import type { ExerciseType } from "@src/types/workout";

    export interface PickedExercise {
      exerciseId: number;
      exerciseCode: string;
      exerciseDisplayName: string;
      exerciseType: ExerciseType;
    }

    // Module-level slot. The builder consumes-and-clears on focus, so we never
    // need subscribers — this is a transient hand-off, not reactive state.
    let pending: PickedExercise | undefined;

    export const setPickedExercise = (picked: PickedExercise): void => {
      pending = picked;
    };

    export const consumePickedExercise = (): PickedExercise | undefined => {
      const value = pending;
      pending = undefined;
      return value;
    };

    // Test-only escape hatch (not used by app code, helpful if a future plan
    // adds tests). Safe to leave exported — it has no runtime cost.
    export const __resetPickedExerciseStore = (): void => {
      pending = undefined;
    };
    ```

    Rationale for module-level singleton over Context:
    - Hand-off is one-shot and ephemeral — no need for re-render notifications.
    - No provider plumbing needed at the app root.
    - Survives navigation because module state lives outside the React tree.
    - Mirrors the diagnosed fix in UAT.md ("simple Zustand atom or React context").

    Path convention: `apps/native/src/state/` is a new directory but follows the existing `src/{hooks,components,context,types}` flat layout. Do NOT put this in `src/hooks/` — it is not a hook, it is plain module state with two functions.

    Do NOT export a hook. Do NOT add a React Context. Do NOT make it reactive.

    ```typescript
    // Pull a picked exercise from the store every time the builder regains focus.
    // This fires after returning from the picker via router.dismiss(2).
    // The store self-clears on consume, so it cannot fire twice for one pick.
    useFocusEffect(

        if (picked) {
          builder.addExercise(picked);
        }
      }, [builder]),
    );
    ```

Listing `[builder]` is lint-clean and the consume-and-clear semantics make the extra invocations harmless: a re-fire with no pending pick returns `undefined` and does nothing.
